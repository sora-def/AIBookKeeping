# 案例：一句话里的两笔支出

用这句话练习「先看 Harness，再怀疑模型」：

> 今天早上地铁花费 3.5 元，购买了瑞幸咖啡花费 9.9 元

期望是两笔待确认账单：交通 3.50 元，用餐 9.90 元（备注里能看出是瑞幸咖啡）。点一次「确认」后，两笔一起写入。

---

## 优化前实际回复了什么

> 我先帮你对一下：今天交通花了 3.50 元，备注「早上地铁花费，购买了瑞幸咖啡花费」。确认的话我就记下啦？

瑞幸和 9.9 元没有单独成账，被塞进了地铁那笔的备注。看起来像模型漏记，其实这句话没有送到模型。

## 原因

记账意图一旦能抽出「金额 + 分类」，`stream_agent` 会在服务端直接建草稿，用来避免模型口头说「已记下」却没有 pending。

旧的 `infer_record` 只保留**第一处**金额和**第一处**分类词：

| 抽出的内容 | 结果 |
| --- | --- |
| 第一个金额 | 3.5 元 |
| 第一个分类词 | 「地铁」→ 交通 |
| 剩下的整句 | 写进备注，包括「瑞幸咖啡」和 9.9 元 |

「咖啡 / 瑞幸」当时也不在分类词表里，所以第二笔永远对不上用餐。

这是 Harness 的抽取规则太粗，不是模型选错了工具。

## 优化后怎么做

仍由服务端建草稿，但按**每一个带「元 / 块 / 万」的金额**把原句切开。每一段各自找分类词：

1. `今天早上地铁花费3.5元` → 交通，备注「早上地铁」
2. `购买了瑞幸咖啡花费9.9元` → 用餐（「瑞幸」「咖啡」都归用餐），备注「瑞幸咖啡」

两笔放进**同一条** `pending_actions`，载荷里是 `items` 数组。回复会说「一共 2 笔」。用户点一次确认，`execute_confirm` 按数组逐笔 `create_record`。

如果某一段有金额、对不上分类，就整句放弃草稿，交给模型追问。这样不会再出现「只记下第一笔、其余被备注吞掉」。

可以自己对一下：

```text
今天早上地铁花费3.5元，购买了瑞幸咖啡花费9.9元
        └──── 第 1 段：交通 3.50 ────┘└──── 第 2 段：用餐 9.90 ────┘
```

## 代码位置

| 步骤 | 文件 |
| --- | --- |
| 按金额切段、匹配分类词 | `abkbackend/app/agent/infer.py` 的 `infer_records` |
| 写意图时直接建草稿，不调用模型 | `abkbackend/app/agent/runner.py` 里 `infer_records` 之后的短路 |
| 一条 pending 里放多笔 | 同文件 `_create_pending_from_inferred`，多笔时 payload 为 `{ items, summary }` |
| 确认后逐笔落库 | `abkbackend/app/services/pending_exec.py` 的 `execute_confirm` |

分类词表在 `infer.py` 的 `_CATEGORY_HINTS`。咖啡、瑞幸、星巴克、奶茶、喜茶目前都归到「用餐」，因为字典里没有单独的咖啡分类；「酒水」留给真正的酒。

## 怎么验证

1. 启动后端和前端，登录后打开「AI 记账」。
2. 发送：`今天早上地铁花费3.5元，购买了瑞幸咖啡花费9.9元`
3. 回复里应同时出现交通 3.50 和用餐 9.90，而不是只有交通。
4. 点「确认」。成功回复里仍是两笔。时间线同一天应能看到交通和用餐各一条。

单笔句子保持原样，例如 `今天午餐花了 28 元` 仍然只确认一笔用餐。
