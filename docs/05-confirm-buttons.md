# 说明：确认和取消按钮增强的是哪一块能力

确认和取消按钮增强的是 **Harness 的安全边界**：写入和删除必须先经人确认。

模型可以提出「要不要记下」。真正落库不由它决定。服务端先放一条待确认草稿，按钮只是让你对这条草稿做决定：

- **确认**执行 `execute_confirm`，这时才写入数据库。
- **取消**执行 `execute_cancel`，草稿作废，不会写入。

它加强的不是模型听懂话的能力，也不是多选一个工具，而是人还留在写入之前。就算模型把「已经记下了」说得很像，没有这条草稿、没有点确认，账也不会进数据库。

## 不要和 `harness.py` 混在一起

对话里说的 Harness，是「提示词、工具、中间件、确认边界」这一整层。`app/agent/harness.py` 只是其中的中间件，负责两件别的事：

- 调用工具前校验分类
- 调用工具后提醒预算

按钮出不出现，不由这个文件决定。

## 按钮什么时候出现

必须同时满足三件事：

1. 服务端已经建好一条仍有效的 `pending_actions` 草稿，并通过 `pending` 事件告诉前端。
2. 前端把这个状态标在当前这条助手回复上。
3. 这条回复已经输出结束。回复还在加载时，不显示按钮，也不能再发下一条。

只有确认口吻、没有草稿时，按钮不会出现。例如「花费了 438」以前没被识别成金额，模型照着确认的口气说了一句，但草稿没建出来，所以只有文字、没有按钮。

「昨天早餐15，午饭30，打车22」是同一类问题：没写「元」，草稿没建成，之后输入「确认」也不会落库。完整推演见 [06-case-amount-without-yuan.md](06-case-amount-without-yuan.md)。

## 代码位置

| 步骤 | 文件 |
| --- | --- |
| 建草稿，并发出 `pending` 事件 | `abkbackend/app/agent/runner.py` |
| 草稿的保存与读取 | `abkbackend/app/services/chat_store.py` |
| 点确认后真正写入，点取消后作废 | `abkbackend/app/services/pending_exec.py` |
| 记下「当前有草稿」 | `abkfrontend/src/composables/useChat.ts` 的 `applyPending` |
| 画出确认和取消 | `abkfrontend/src/components/ChatTab.vue` |

点按钮不会再让模型决定写不写。前端只是发送「确认」或「取消」，`runner.py` 认出这两个短句后，直接执行上面的确认或取消。

## 删除走同一条边界

「删掉 9.90 元的咖啡，我记错了」里的「改」是「该记录」，不是把金额改成 9.90。这句话包含「删」，意图是删除。

以前会把整句交给模型。模型可能回答「我帮你修改成 9.90 元」，既没有删，也没有待确认草稿，所以确认和取消都不会出现。

现在删除和记账一样，在调用模型之前处理：

1. 用金额、事项（咖啡归用餐）和备注去已有记录里找。
2. 找到就建一条 `action_type=delete` 的草稿，回复里说明要删的是哪一天、哪一类、多少钱。
3. 确认后才真正删除；取消则保留原记录。
4. 找不到就直接说明没删，不改成一笔新的修改。

对应代码在 `infer.py` 的 `pick_delete_targets`，以及 `runner.py` 里删除意图的那段短路。
